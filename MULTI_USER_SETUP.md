# Adding a New User

## Admin side

### 1. Create the user

```bash
sudo add-dev-user <username>
```

This creates the Linux user, installs dev-cli and Claude Code, sets up groups and PATH. Note the temporary password printed at the end.

### 2. Share credentials

Send the new user:
- Temporary password (they'll be forced to change it on first login)
- Server hostname: `ssh <username>@patagon`

### 3. Verify (optional)

After they log in, check the shared registry:

```bash
cat /etc/dev-cli/ports.json   # their sessions should appear here
```

---

## User side

### 1. First login

```bash
ssh <username>@patagon
```

You'll be prompted to change your password immediately.

### 2. Authenticate services

```bash
gh auth login       # GitHub — follow the prompts
claude login        # Claude Code — opens browser auth
```

### 3. Verify setup

```bash
dev doctor          # all tools should be green
```

### 4. Fix ports.json (if needed)

If `dev doctor` shows "ports.json — invalid JSON!", run:

```bash
echo '{}' > ~/.config/dev-cli/ports.json
```

### 5. Start working

```bash
dev init <project>              # set up a project (first time only)
dev new <project> <branch>      # create a session
dev ls                          # list your sessions
```

## How `.env` files work

Each session runs in its own git worktree with its own ports, so every session needs its own `.env` files. `dev-cli` generates these automatically — you just need to understand the two modes.

### Standard repos (single `.env`)

For a normal (non-monorepo) project, `dev init` creates an **env template** at:

```
~/.config/dev-cli/templates/<project>.env
```

This template uses `{{PLACEHOLDER}}` syntax for values that change per session:

```bash
# Example template
PORT={{FRONTEND_PORT}}
NEXT_PUBLIC_PORT={{FRONTEND_PORT}}
BACKEND_PORT={{BACKEND_PORT}}
NEXT_PUBLIC_SUPABASE_URL=http://localhost:{{SUPA_API_PORT}}
MY_API_KEY=sk-hardcoded-value-here
```

Available placeholders: `{{FRONTEND_PORT}}`, `{{BACKEND_PORT}}`, `{{SUPA_API_PORT}}`, `{{SUPA_DB_PORT}}`, `{{SUPA_STUDIO_PORT}}`, `{{SLOT}}`, `{{IP}}`

When you run `dev new`, the CLI copies the template into the worktree as `.env.local`, replacing all placeholders with the actual port values for that session's slot.

To edit the template: `dev template <project>`

### Monorepos (multiple `.env` files)

Monorepos like Patagon have multiple packages that each need their own `.env`. A simple template with placeholders can't handle that, so `dev init` generates a **setup hook** instead — an executable bash script at:

```
~/.config/dev-cli/hooks/<project>/setup.sh
```

This script runs after each worktree is created and has access to environment variables set by the CLI:

| Variable | Example |
|---|---|
| `DEV_SLOT` | `3` |
| `DEV_WORKTREE` | `/home/user/worktrees/patagon-feat-auth` |
| `DEV_FRONTEND_PORT` | `3003` |
| `DEV_BACKEND_PORT` | `4003` |
| `DEV_SUPA_API_PORT` | `54351` |
| `DEV_IP` | `100.64.0.5` |

The hook writes a separate `.env` into each package directory:

```bash
# What the hook does (simplified):
cat > "$DEV_WORKTREE/apps/web/.env" << EOF
PORT=$DEV_FRONTEND_PORT
NEXT_PUBLIC_SUPABASE_URL=http://localhost:$DEV_SUPA_API_PORT
EOF

cat > "$DEV_WORKTREE/apps/api/.env" << EOF
PORT=$DEV_BACKEND_PORT
DATABASE_URL=postgresql://postgres:postgres@localhost:$DEV_SUPA_DB_PORT/postgres
EOF

cat > "$DEV_WORKTREE/.env.local" << EOF
DEV_SLOT=$DEV_SLOT
EOF
```

To edit the hook: `dev template <project>` (opens the hook for monorepos)

### Hook priority

When `dev new` creates a session, it looks for setup scripts in this order:

1. **In-repo hook** — `.dev/setup.sh` inside the repo itself (checked into git)
2. **Global hook** — `~/.config/dev-cli/hooks/<project>/setup.sh` (generated by `dev init`)
3. **Default** — Falls back to the env template at `~/.config/dev-cli/templates/<project>.env`

### Adding secrets

For values like API keys that are the same across all sessions, just hardcode them directly in the template or hook — they aren't session-specific so they don't need placeholders.

On shared servers, shared secrets live in `/etc/dev-cli/secrets/` and are symlinked into each user's config automatically.

## Tips

- **SSH keys**: Set up key-based auth to skip password entry: `ssh-copy-id <username>@patagon`
- **tmux**: Sessions persist after disconnect. Reconnect with `dev attach <session>`
- **Shell customization**: Users can edit their own `~/.bashrc` freely — Homebrew and nvm are already sourced
- **Shared secrets**: API keys and env files are symlinked from `/etc/dev-cli/secrets/` into each user's config automatically

## Troubleshooting

| Problem | Fix |
|---|---|
| "Permission denied" on ports.json | User isn't in `devs` group. Run `sudo usermod -aG devs <user>`, then they re-login |
| `claude: command not found` | Re-run: `sudo su - <user> -c 'curl -fsSL https://claude.ai/install.sh \| bash'` |
| `dev: command not found` | Re-run: `sudo su - <user> -c "bash /opt/dev-cli/install.sh"` |
| flock errors on ports.json | Ensure `/etc/dev-cli` has group write: `sudo chmod g+ws /etc/dev-cli` |

## Removing a user

```bash
sudo su - <username> -c "dev kill --all"   # clean up their sessions
sudo userdel -r <username>                 # remove user and home dir
```
